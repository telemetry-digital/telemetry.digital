Redundant database

  

    
This server

    
Functions

      

        
One-time copy
Copy the live database to another PC, then detach it safely: verified, complete, independent (archive, move, test system).

        
Continuous replica
A read-only copy at another site that follows every change within seconds; incident when it falls behind or disconnects.

        
Hot standby
A complete server ready to take over; promoted manually on the standby when the primary fails; the old primary then refuses writes.

      

      
A replica is not a backup: deleted or damaged data is copied too. Keep the backups.

Detach safely

      
The primary counts its records and writes a detachment entry; the replica catches up to it, becomes an independent database and verifies the audit chain and the counts. The primary keeps collecting data.

      
      
      

      

    

  





  
Updates

  

  

    

    

      
      
      
The agent downloads the release from the distribution point, verifies its SHA-256 checksum, runs the schema migrations and restarts the service. Make a database backup first for major upgrades.
