# Data Model: Redundant database (migration 0022)

## core.node — this database's identity (one row)
| column | type | notes |
|---|---|---|
| id | uuid PK | node id, generated by the migration |
| created_at | timestamptz | |
| promoted_from | uuid null | node id of the primary this database was promoted from |
| epoch | int | 1 on a fresh install; +1 on every promotion |

A physical replica carries the primary's row; on promotion the new primary replaces `id`/`epoch` in a single
guarded update (the only allowed change).

## core.replica — replicas attached to this primary
| column | type | notes |
|---|---|---|
| id | uuid PK | |
| name | text | from pairing, ≤ 64 |
| mode | text | `copy` \| `continuous` \| `standby` |
| state | text | `pairing` `copying` `in_sync` `lagging` `disconnected` `detaching` `detached` `failed` `lost` `dropped` |
| token_hash | bytea | SHA-256 of the replica token |
| role_name, slot_name | text | `ctrl32_repl_<short>` / `ctrl32_replica_<short>` |
| standby_url | text null | hot standby: its public base URL (fencing checks) |
| host_info | jsonb | hostname, OS, PostgreSQL and ctrl32 versions at pairing |
| lag_limit_s | int | default 10 (continuous/standby), alarm threshold |
| max_retained_mb | int | default 10240 → `max_slot_wal_keep_size` (the largest of all replicas) |
| copy_total_bytes, copy_done_bytes | bigint | base copy progress |
| lag_s, lag_bytes | numeric/bigint | last measurement |
| last_contact | timestamptz | last tunnel/command contact |
| command | jsonb null | pending command for the replica (`detach`) |
| detach | jsonb null | detachment record: seq, hash, snapshot, counts, verification, partial |
| created_by, created_at, updated_at | | |

Configuration (mode, limits) changes go through the API with a reason and are audited (old/new).

## core.replica_pairing — one-time codes
| column | type | notes |
|---|---|---|
| id | uuid PK | |
| code_hash | bytea unique | SHA-256 of the normalised code |
| mode, name | text | chosen when the code was created |
| created_by | uuid | admin |
| expires_at | timestamptz | created_at + 15 min |
| used_at, replica_id | | set once |

## core.replica_event — append-only history
`id, replica_id, ts, kind (state|alarm|command|detach|promote|security), detail jsonb` — `core.make_append_only`.

## Files outside the database
- Replica node: `<config dir>/replica.json` (0600): primary URL, replica id, token, tunnel port, mode.
- Fenced primary: `<config dir>/fenced.json`: fenced at, by node, standby URL.

## State transitions (replica)
`pairing → copying → in_sync ⇄ lagging ⇄ disconnected → (lost)`; any connected state → `detaching → detached |
failed`; standby → `promoted` (on the standby's own record); admin drop → `dropped`.
